# مسیر یادگیری

هر مرحله یک تگ Git دارد. برای دیدن کد همان مرحله: `git checkout <tag>`؛ برای دیدن تغییرات یک مرحله: `git show --stat <tag>` یا `git diff <tag-قبلی> <tag>`.

| تگ | موضوع |
|---|---|
| `step-01-domain` | هسته مالی خالص، schema، سرویس‌ها و تست‌ها |
| `step-02-ui` | احراز هویت، رابط کاربری RTL، PWA و صف آفلاین |
| `step-03-deploy` | استقرار production با Docker، بکاپ و rollback |
| `step-04-login-links` | ورود بدون ایمیل با لینک شخصی |
| `step-05-restyle` | بازطراحی ظاهر |
| `step-06-phase2` | تولد، ویش‌لیست، فضای سورپرایز، هدیه گروهی، نظرسنجی |
| `step-07-public` | آماده‌سازی برای انتشار: تنظیمات قابل‌پیکربندی استقرار، CI، مستندات |

## مرحله ۱ — هسته مالی (`step-01-domain`)
**بخوانید:** `src/domain/split.ts`، `src/domain/ledger.ts`، `src/domain/simplify.ts`، `drizzle/0001_integrity_triggers.sql`، `src/server/expenses.ts`.

**نکات کلیدی**
- چرا پول `bigint` است و در JSON رشته؛ مشکل `0.1 + 0.2` و تقسیم ۱۰۰٬۰۰۰ بر ۳.
- روش «بزرگ‌ترین باقیمانده» برای اینکه جمع سهم‌ها **دقیقاً** برابر کل باشد و نتیجه قطعی (deterministic) باشد.
- مانده مشتق‌شده در برابر مانده ذخیره‌شده.
- تست property-based با `fast-check`: به‌جای چند مثال، یک «قانون» را روی هزاران ورودی تصادفی بررسی می‌کنیم (مثلاً «جمع مانده‌ها همیشه صفر است»).
- idempotency: چرا ارسال دوباره یک درخواست نباید دو هزینه بسازد.
- قفل گروه (`pg_advisory_xact_lock`) و تریگرهای deferred برای حفظ یکپارچگی.

**تمرین‌ها**
1. نوع تقسیم پنجم «بر اساس اقلام رسید» اضافه کنید (هر قلم به چند نفر). اول تست property بنویسید.
2. ثابت کنید (با تست) که `suggestTransfers` هیچ‌وقت بیش از `n−1` انتقال پیشنهاد نمی‌دهد. مثالی بیابید که حریصانه بودنش کمینه مطلق نیست.
3. یک تست یکپارچه بنویسید که دو `createExpense` هم‌زمان با یک کلید idempotency فقط یک رکورد بسازند.

## مرحله ۲ — رابط کاربری و آفلاین (`step-02-ui`)
**بخوانید:** `src/server/auth.ts`، `src/lib/session.ts`، `src/components/SyncProvider.tsx`، `src/lib/offline/queue.ts`، `public/sw.js`.

**نکات کلیدی**
- ورود با لینک جادویی: ذخیره فقط هش توکن، یک‌بارمصرف، و مصرف با POST (نه با باز کردن لینک).
- کوکی `HttpOnly; Secure; SameSite=Lax` و پیشوند `__Secure-`.
- چرا Service Worker فقط پوسته اپ را کش می‌کند و هرگز داده مالی را.
- صف آفلاین جدا برای هر حساب و پاک شدن آن هنگام خروج.

**تمرین‌ها**
1. ویرایش هزینه را هم آفلاین‌پذیر کنید. تعارض نسخه (`version`) را چطور مدیریت می‌کنید؟
2. یک تست e2e بنویسید که قطع اینترنت هنگام ثبت تسویه را پوشش دهد.

## مرحله ۳ — استقرار (`step-03-deploy`)
**بخوانید:** `deploy/Dockerfile`، `deploy/compose.yml`، `deploy/remote-deploy.sh`، `docs/operations.md`.

**نکات کلیدی**
- image چندمرحله‌ای، کاربر غیر root، خروجی standalone در Next.js.
- دیتابیس روی شبکه `internal: true`: نه پورت باز، نه اینترنت.
- استقرار با بکاپ پیش از migration، health check و تطبیق نسخه.
- migration «رو به جلو و افزایشی» (expand/contract) و اینکه چرا rollback فقط کد را برمی‌گرداند.

**تمرین‌ها**
1. پروژه را روی یک VPS یا ماشین مجازی خودتان با `deploy/deploy.sh` مستقر کنید.
2. یک ستون را «حذف» کنید، به‌شکل امن و در دو انتشار (expand/contract).

## مرحله ۶ — تولد و حریم خصوصی (`step-06-phase2`)
**بخوانید:** `docs/phase2-plan.md` (مثال عددی حسابداری هدیه)، `src/domain/gifts.ts`، `src/server/access.ts` (`requireSpaceMember`)، `drizzle/0004_phase2_privacy_triggers.sql`، `tests/integration/phase2.test.ts`.

**نکات کلیدی**
- پنهان‌سازی فقط در UI کافی نیست: API، HTML اولیه، داده RSC، اعلان‌ها، فعالیت، شمارنده‌ها و مانده‌های تجمیعی هم باید بررسی شوند.
- «محدوده دفتر» (ledger scope): پول خصوصی هرگز وارد دفتر عمومی نمی‌شود.
- سه مفهوم جدا: تعهد ≠ پول منتقل‌شده ≠ هزینه نهایی؛ و اینکه چرا هیچ پولی دو بار شمرده نمی‌شود.
- رزرو انحصاری با قفل ردیف + unique index جزئی.
- حالت نتیجه تجمیعی نظرسنجی و صادق بودن درباره اینکه «کاملاً ناشناس» نیست.
- محافظ rollback که داده واقعی را بررسی می‌کند (`deploy/rollback.sh`).

**تمرین‌ها**
1. یک مسیر جدید اضافه کنید (مثلاً خروجی CSV مانده‌ها) و با تست ثابت کنید داده فضای خصوصی در آن نشت نمی‌کند.
2. «فاش کردن سورپرایز بعد از جشن» را طراحی و پیاده کنید: چه کسی، چه زمانی و چه چیزی را ببیند؟
3. یک ارائه‌دهنده قیمت نمونه بر اساس `src/server/prices/providers.ts` و `safeFetchText` بسازید و با سرور محلی ساختگی تست کنید (اتصال به سرویس واقعی بدون مجوز آن ممنوع).

## پروژه‌های بزرگ‌تر (مرحله ۳ محصول)
- اقساط توافقی: بدهی موجود را زمان‌بندی کند، بدهی تازه نسازد.
- کار خیر: هدف مالی، مشارکت آزاد، گزارش هزینه، نمایش اختیاری نام.
- Web Push برای یادآوری‌ها (با رضایت کاربر).
- حالت تیره با توکن‌های رنگی موجود در `src/app/globals.css`.
